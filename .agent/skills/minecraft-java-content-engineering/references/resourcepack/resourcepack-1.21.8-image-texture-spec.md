# 이미지 규격과 텍스처 규칙 (1.21.8)

## 목차

1. 기본 규격
2. 바닐라 치수 분포(실측)
3. 텍스처 작성 규칙
4. 애니메이션 `png.mcmeta`
5. 카테고리별 주의점
6. 품질 체크리스트

## 1) 기본 규격

- 기본 포맷: `PNG`
- 알파 채널: 투명도 필요 자산은 RGBA 사용
- 권장 색공간: sRGB 기반 워크플로우
- 기본 해상도 기준: 16px 단위(바닐라 기준)

실무 규칙:
- 픽셀아트 스타일이면 nearest-neighbor 스케일링 유지
- 고해상도 팩은 카테고리별 배율을 일관되게 유지(예: 32x, 64x)

## 2) 바닐라 치수 분포(실측)

| 치수 | 파일 수 |
|---|---:|
| 16x16 | 1938 |
| 64x64 | 290 |
| 64x32 | 166 |
| 8x8 | 148 |
| 32x32 | 130 |
| 9x9 | 65 |

해석:
- `block`, `item`은 16x16 비중이 압도적
- `entity`, `gui`, `painting`, `particle`은 다양한 치수가 섞인다

## 3) 텍스처 작성 규칙

1. 경로 규칙
- 예: `assets/minecraft/textures/block/stone.png`
- JSON 참조는 확장자 제외: `minecraft:block/stone`

2. 네이밍
- 소문자 + 언더스코어 권장
- 공백/대문자/로케일 문자 피하기

3. 성능
- 불필요한 초고해상도 남발 금지
- 자주 렌더되는 GUI/아이템/블록은 용량과 품질 균형 유지

## 4) 애니메이션 `png.mcmeta`

애니메이션 텍스처는 같은 경로에 `*.png.mcmeta`를 둔다.

### 최소 예시

```json
{
  "animation": {}
}
```

### 프레임타임/보간 예시

```json
{
  "animation": {
    "frametime": 4,
    "interpolate": true
  }
}
```

### 프레임 순서 지정 예시

```json
{
  "animation": {
    "frames": [0, 1, 2, 3, 2, 1],
    "frametime": 2
  }
}
```

주의:
- `png.mcmeta`가 있는데 대응 `png`가 없으면 로드 실패/무시 원인 된다.
- 애니메이션 프레임 배치는 텍스처 시트 분할 규칙에 맞춰야 한다.

## 5) 카테고리별 주의점

### `textures/block`

- 가장 많이 쓰이는 영역
- 타일링 이음새(seam) 검수 필수

### `textures/item`

- 바닐라 1.21.8 기준 대부분 16x16
- GUI 표시 품질과 인벤토리 가독성 우선

### `textures/gui`

- 9x9, 18x18, 256x256 등 다양한 규격 혼합
- 슬롯/패널 가장자리 픽셀 정렬이 어긋나기 쉬움

### `textures/entity`

- 64x32, 64x64, 128 계열이 자주 등장
- UV 맵을 확인하지 않고 치수만 바꾸면 왜곡 발생

## 6) 품질 체크리스트

1. PNG 알파/색상 깨짐 없음
2. 경로 대소문자 오류 없음
3. `png.mcmeta` 쌍 불일치 없음
4. 고해상도 자산의 프레임 저하 없음
5. GUI/아이템/엔티티 실제 렌더 검수 완료
