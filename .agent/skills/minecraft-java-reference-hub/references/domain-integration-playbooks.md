# 도메인 통합 플레이북

## 목차

1. 통합 설계 원칙
2. 플레이북 A: 퀘스트 시스템
3. 플레이북 B: 서버 경제 밸런스
4. 플레이북 C: RP 상호작용 시스템

## 1) 통합 설계 원칙

1. 도메인 2개씩 끊어서 구현한다.
2. 인터페이스(명령 진입점, 파일 경로, 상태 키)를 먼저 정의한다.
3. 통합 후에는 성능/권한/롤백을 별도 점검한다.

## 2) 플레이북 A: 퀘스트 시스템

대상 도메인:
- 발전과제
- 스코어보드
- 루트 테이블
- 데이터팩

순서:
1. 진행 상태 objective 설계
2. advancement criterion 연결
3. 보상 loot table 연결
4. tick 함수 최소화
5. 회귀 테스트(신규/기존 플레이어)

## 3) 플레이북 B: 서버 경제 밸런스

대상 도메인:
- 루트 테이블
- 아이템
- 마법부여
- 상태 효과

순서:
1. 경제 지표 정의(시간당 획득량)
2. 드롭 확률 조정
3. 강화/효과 조합 상한 설정
4. 악용 시나리오 테스트
5. 패치 후 24시간 모니터링

## 4) 플레이북 C: RP 상호작용 시스템

대상 도메인:
- 다이얼로그
- 발전과제
- 플레이어/권한
- 명령어

순서:
1. 분기 트리 설계
2. 상태 전이 정의
3. 보상/제약 연결
4. 권한 경계 테스트
5. 장애 시 fallback 대사/경로 제공
